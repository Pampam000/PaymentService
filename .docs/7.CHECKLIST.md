# Этап 7 — журнал приёмки

## 7.1 Автоматические проверки

- [x] CI поднимает отдельную PostgreSQL, применяет и проверяет миграции, запускает тесты, Ruff и аудит закреплённых зависимостей.
- [x] Тесты с управляемыми ответами провайдера проверяют деньги, повторы создания платежа и возврата, конкурентные запросы, поддельный webhook, потерю ответа и сверку.
- [ ] Убедиться, что все проверки CI проходят в GitHub Actions.

## 7.2 Тестовый магазин — выполняет оператор

Все обращения к ЮKassa выполняются вручную. Для каждого сценария записать дату UTC, локальный ID, ID ЮKassa, ожидаемый и фактический статус, сумму, результат в БД и ссылку на защищённый журнал. Токены, данные карт и тело webhook не сохранять.

| Сценарий | Локальный ID | ID ЮKassa | Ожидалось | Получено | Итог |
| --- | --- | --- | --- | --- | --- |
| Успешная оплата | | | `succeeded`, одно событие Backend | | |
| Отмена/неуспех | | | `canceled`, доступ не выдан | | |
| Полный возврат | | | `succeeded`, один возврат и событие | | |
| Повторный webhook | | | статус и число событий не меняются | | |
| Потеря ответа | | | `pending + unknown`, сверка с исходным ключом | | |
| Webhook отключён | | | плановая сверка восстанавливает статус и событие | | |
| Чек, если требуется | | | данные соответствуют выбранному магазину | | |

- [ ] Все расхождения исправлены и проверены повторно.
- [ ] В тестовой БД нет необъяснённых `unknown`.

Частичный возврат проверить после этапа 9.
